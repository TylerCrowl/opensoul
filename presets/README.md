# presets/

Data files the UI shows as tiles and the GPU side consumes.

- `camera/*.json`, `effects/*.json`: `id`, `label`, `blurb`, `prompt` (long cinematographer-style recipe), `lora` (LTX LoRA reference or `null` for prompt-only moves), `defaults` (duration, fps, cfg, steps, 704x1280), `thumbnail` (looping 9:16 MP4 path; the UI shows an animated placeholder until the file exists under `assets/preset_thumbs/`). `expect_motion`: the camera move the finished clip must show, checked after every live take by `opensoul/motion_check.py` (optical flow); a take that moves the wrong way is re-seeded (up to 2 times) and the result says "fixed automatically: camera direction". Labels: `static`, `zoom_in`, `zoom_out`, `truck_left/right`, `orbit_left/right` (or `orbit` for either), `crane_up/down`, `pan_left/right`, `tilt_up/down`, a list of them, or `"any"` for looks that are not one camera move (dolly zoom, outfit switch). `experimental` (true = not working well enough yet on the default model; the tile shows an "Experimental" tag) and `verified` (`model`, `path`: prompt or lora, `result`, `checked_by`, `evidence`): what was checked on which model, so the tiles never claim more than was tested. Camera presets also carry `phrase`: one short clause used when moves are stacked. `camera_rules.json`: up to `max_moves` (3) per shot; moves under `alone` can't be combined; `conflicts` pairs (with the plain-English `why` shown in the shot sheet) can't share a shot. A stack is prompt-only (no LoRA) and joins the phrases in order ("First …; then …; finally …"); the motion check looks at the first move. Optional `reverse: true` + `render_prompt`: render the opposite move (`render_prompt`, `lora`) and play the frames backwards with ffmpeg (video only), e.g. Earth zoom out = a zoom-in onto the character reversed; the reversed clip ends on the user's picture. A camera move picked together with a reverse effect is not added.
- `eras.json`: prompt suffix + ffmpeg post params (grain, shake, vignette).
- `voices.json`: TTS voice ids for the Speak tab.
- `character_sheet.json`: the one-tap Character Sheet: six views (`id`, `label`, `prompt` with `{subject}`, `seed_offset`), the shared `keep` (identity lock) and `style` (light gray, same lighting) text, `negative`, `grid` (3×2 cell size and background), `gate` (backend, threshold, retries) and `sampler`. Read by `opensoul/character_sheet.py` → `workflows/07_character_sheet_api.json`.

`opensoul/presets.py:build_shot_plan` maps a choice to `workflows/04_i2v_ltx_api.json` node inputs (node 1 image, node 20 text, nodes 35/43 seed, output node 51), with optional TTS (03) and lip-sync (05) stages. LoRA compatibility with LTX-2.5 is still unverified (see docs/HIGGSFIELD_TEARDOWN.md).
