# Soul ID (OpenSoul's open-weights identity lock)

Higgsfield's Soul ID trains an identity from photos. OpenSoul's open equivalent, as used for the first demo character's v4:

1. **Canonical photoreal anchor.** Qwen-Image-Edit-2511 (no Lightning LoRA, 28 steps, CFG 4, anti-CG negative prompt) turns the
   approved character sheet into one candid phone-photo portrait (`ref_00`). This look was approved as canonical.
2. **Reference set.** Every further image (20+ angles, expressions and lighting setups) is generated by editing *from the anchor
   photo*, not from the sheet. That keeps the face, glasses and cap consistent.
3. **Identity gate.** ArcFace (insightface `buffalo_l`) cosine similarity against the anchor. References score 0.69–0.75.
   Accept start frames at ≥ 0.6 and video frames at mean ≥ 0.5. The old CG-sheet-derived v3 shots scored 0.18–0.33, a different person.
4. **Video.** LTX-2.5 image-to-video or audio-to-video from gated start frames (the frame-0 image conditioning is the identity carrier).
   Then LatentSync 1.6 at 30 steps redoes the mouth region only, which keeps the identity.
5. **Character LoRA (in progress).** LTX-2.5 trainer (`Lightricks/LTX-2`, packages/ltx-trainer) with an image-only dataset
   (`768x768x1` buckets) built from the reference set, a character trigger token, trained on the dev transformer. See ASSET_PROVENANCE.

**In the app (one tap): Character Sheet → Soul Pack.** The Character step turns one photo (or a generated character) into a six-view
turnaround (full body and close-up, front / side / back, light gray, same lighting) with `workflows/07_character_sheet_api.json`.
Every view passes the `OpenSoulIdentityGate` node (patch backend by default) and an off-model view is re-rendered once with a new
seed. The six views are written into the pack (`refs/sheet_*.png`, `meta.soul_pack`) after the original photo, so later stills
are gated against six angles.

**Auto-fix (self-correcting sheet).** The patch gate alone overrates (it passed close-ups that came out full-body),
so every view is also checked by a local open VLM (Qwen3-VL-8B-Instruct, Apache-2.0, loaded on demand and released after
each round; it waits until at least 12 GB stays free). It reads the reference once into an attribute checklist
(headwear + orientation, glasses, sunglasses on the cap, earbuds/earrings per ear, facial hair, clothing items and
colours) and then asks each view yes/no questions with the answer expected *for that view*: a backwards cap shows its
strap in front views and its brim toward the camera in back views, one earbud means "earbuds in both ears?" must be
no, side views must face the left edge of the image, close-ups must not show legs. Identity uses ArcFace where a face
is visible (optional, non-commercial weights), else the patch gate. Each failed check becomes a corrective prompt
line ("Only ONE earbud, in the person's left ear…"); the view is re-rendered with a new seed, up to 2 retries, the
best try is kept, and a view still failing is flagged in the UI with a Regenerate button. Code: `opensoul/sheet_check.py`. When a back view fails twice, it is re-rendered from the sheet's own side view (workflow 07b) or with visor wording that avoids "backwards cap" (preset `back_fallback`); from behind, the cap is checked by asking whether its strap is visible.

Only for original characters or the user's own photos (consent checkbox). Code:
`opensoul/character_sheet.py`, CLI `scripts/sheet_run.py`. First GPU run: [evidence/CHARACTER_SHEET.md](evidence/CHARACTER_SHEET.md).

Scripts: `scripts/spark_render_jobs.py`, `scripts/idsim.py`, `scripts/spark_latentsync.sh`; workflows `02r*`, `a2v_hq*`, `i2v_hq*`.
